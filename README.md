# 猫眼 AutoX 抢票工作台

Windows 本机工作台与 Android AutoX 脚本：配置目标演出，生成并传送手机端脚本，自动选择指定场次、票档及 1 张票，点击票档确认后核对指定实名观演人的勾选状态。正式脚本可单次提交订单，核对猫眼支付订单弹窗后尝试唤起微信；进入微信后停止，付款由使用者决定。

这是从本机开发版本独立整理的源代码项目。**不包含 Cityline、真实观演人资料、设备序列号、手机截图、登录资料或针对个人生成的脚本**。原本机项目保持不变。

## 启动

1. 安装 Python 3.13；首次运行 `setup.bat` 安装独立环境，然后双击 `Start.bat`。
2. 手机安装 AutoX v7、开启其无障碍服务；USB 模式还须开启并授权 USB 调试。
3. 从 [Google 官方](https://developer.android.com/tools/releases/platform-tools) 下载 Windows Platform Tools，将 adb.exe 和随附文件解压至 `tools/platform-tools/`。本仓库不携带 ADB 二进制。
4. 工作台选择 **猫眼**，填写官网实际演出标题、城市、日期、票档、开售时间及唯一观演人，保存并选中目标。仓库没有个人资料，首次启动必须自行填写。
5. 先运行 USB 只读探测，再在可售页面做 **选票档演练（不下单）**。真实尝试使用 **猫眼 AutoX 手机端**；按手机提示运行脚本后返回目标演出详情页。

现有工作台仍保留历史大麦适配与回归模块，以维持当前版本的依赖和测试；猫眼的运行方式是 AutoX 手机端。`config/target.json` 为历史大麦测试所用的公开演出样例，**不是猫眼当前选中的个人目标**。

## 能力及边界

- 演出目标在本机 `data/profiles.json` 保存，可管理多场演出。
- 只读探测、离线模拟、手机脚本生成及 USB 传送。
- 猫眼前台及目标核对、指定场次和票档识别、选档生效检查、确认跳转、指定观演人勾选检查。
- 每个阶段读取一次原生控件树后复用，点击后重新读取；状态不明、不可售、验证或页面变化时停止。
- 单次尝试标记及阶段耗时记录；不把点击完成或局部耗时当成抢票成功。

真实可售票档、“确认”跳转和观演人完整流程仍须 Android 真机验收。此前只读样本及离线测试不是成功率或毫秒抢票保证。脚本不代答人机验证，不保存支付密码，可按用户指定目标提交订单，但不操作微信最终确认付款。

## 测试与文档

运行 `Test.bat`；AutoX 离线模拟还需要 Node.js，缺少 Node.js 时部分测试会跳过。测试不连接手机、不生成真实订单。完整使用与已验证范围见 [手机脚本说明](autox/README.md)、[验收记录](docs/验收记录.md) 和 [开源项目比较](docs/项目对比与选型.md)。

## 隐私与第三方代码

`data/`、生成脚本、结果日志、截图、尝试锁和浏览器/账号信息不纳入 Git。生成脚本含观演人姓名摘要，摘要也属于个人配置，请勿上传。分享运行记录前须检查并清除个人信息。

大麦历史适配包含 HaTickets v0.5.0 的 mobile/shared 源码；来源、固定版本及本地修改记录位于 `vendor/source.json`。保留了上游 Apache-2.0 [LICENSE](vendor/HaTickets/LICENSE) 与 [NOTICE](vendor/HaTickets/NOTICE)。AutoX 需要单独安装，本项目不分发其安装包。

## 最新优化

正式入口为“打开 AutoX 到微信付款页脚本（不付款）”。可随时传送文件；运行请在开售前10分钟到开售后20分钟内启动，20秒内回到目标演出详情页。票档来源可选工作台填写或开抢前明确记录的手机预选。任意明确票档可配置，预选丢失后补选固定目标；订单实际金额必须与目标一致。手机预选须先记录，24 小时内有效。首击采用1ms短按；拥堵弹窗支持识别后刷新；进入微信不发送点击、输入或手势。详细用法与限制见[手机端说明](autox/README.md)，测试证据见[优化验收](docs/优化验收-20261012.md)。
