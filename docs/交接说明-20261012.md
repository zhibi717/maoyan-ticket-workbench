# 猫眼工作台交接说明（2026-10-12）

本包是 Windows 工作台与 Android AutoX 手机脚本的完整开发源码。解压后可配置不同猫眼演出、场次和票档，当前正式脚本限定 1 张票、1 位观演人；1380 元只是某次配置，并非代码固定票档。Cityline 项目独立保留，不在本包内。

## 对方先看哪些文件

- `README.md`：环境安装和启动方法。
- `autox/README.md`：手机运行步骤、预约记录和正式流程。
- `autox/maoyan_live_template.js`：手机原生控件识别、入口等待、选档、确认、观演人、订单和支付方式流程。模板默认锁定，由工作台根据本机资料生成正式文件。
- `ticketdesk/autox_live_export.py`：本机目标转成手机脚本，生成姓名摘要及不同运行模式。
- `ticketdesk/autox_phone.py`：通过 USB 传送并打开脚本。
- `ticketdesk/web/`、`ticketdesk/server.py`、`ticketdesk/controller.py`：工作台页面、接口与运行状态。
- `tests/autox_live_mock.js`、`tests/test_autox_live_export.py`：离线合成控件树与流程回归。
- `docs/验收记录.md`、`docs/四页流程与入口优化-20261012.md`：已有证据与尚未验证的范围。

## 当前正式流程

1. 用户在猫眼保存预约，在本机工作台选中演出及票档；也可先记录手机上明确预选的票档，记录限本演出且 24 小时内有效。
2. 工作台传送脚本。手机启动后有 20 秒切回猫眼目标详情页；正式运行窗口为开售前 10 分钟至开售后 20 分钟。
3. 等待开售，识别同一演出及城市下唯一可用购票入口。进入选票页后停止入口重试。
4. 核对场次、沿用或补选明确目标票档和 1 张；自动点唯一可用的票档“确认”一次。
5. 核对订单的演出、日期、金额、数量、指定观演人。完整姓名可补勾一次；掩码姓名只兼容匹配且已预选的唯一观演人。提交订单一次。
6. 猫眼“支付订单”弹窗核对其自身金额、已选微信方式和唯一按钮后，点猫眼的“确认支付”尝试唤起微信一次。到微信付款页停止，最终付款由用户完成。

选档演练只选择票档，不点击票档确认或提交。图片、滑块、短信等验证需要用户处理，脚本不会代答。

## 本轮失败与修复

李大奔广州站的固定坐标实验在第一下触摸前停止。结果记录显示触摸轨迹为空、入口点击时间为空；最后检查错误要求仍显示“已预约”，而临近开售该状态已切换。此次修复让启动预检和开售前检查接受同一目标下的预约状态或购票入口，仍到开售时间后才触摸。

正常工作台入口增加有限重试：每次重新读取后必须仍确认同一详情页和唯一可用入口，触摸起点至少间隔 250 毫秒，总计最多 3 次。新页、加载或验证提示不使用旧坐标连点。触摸调用返回失败时仍立即停止，不补点；订单提交和微信唤起仍各一次。

曾试图省掉选票确认前的一次新读取，回归发现会漏掉临时变化的预选状态和验证提示，已撤回。当前保留确认前的新页核对。

固定坐标实验不作为工作台默认正式流程。此前借用其他演出的票档位置不适配李大奔的两列布局，实验启动器已停用且不打包。源码里的固定路径构建函数仅保留用于研发与回归，不应直接拿其坐标用于另一场演出。

## 真机验证还缺什么

已获得详情页只读识别和本地触摸样本；尚未完成 Android 猫眼真实可售目标票档至微信付款页的完整验收。后续应在用户授权的可售票档上先验证“选中正确档位、数量为 1、确认生效、到达正确订单页”，再分别记录入口触摸、App 跳页、原生控件读取和订单处理时间。

`press(x,y,1)` 的 1 毫秒是按压参数。本地按钮测速、离线测试或发现至触摸指标不能说明整段抢票只需几毫秒，也不能保证库存或抢票成功。

## 压缩包内容与运行

源码、页面、测试、公开样例配置、依赖清单、第三方许可证和本说明已整合；不带个人 `data/`、生成的实名脚本、截图、日志、尝试锁、虚拟环境、Cityline、AutoX APK 或 ADB 二进制。`data/.gitkeep` 只是空目录占位，首次启动须自行填写资料。

安装 Python 3.13，运行 `setup.bat`，再运行 `Start.bat`。安装 Android AutoX v7 并开启无障碍，按 `README.md` 从 Google 官方下载 Windows Platform Tools。开发测试另需 Node.js，运行 `Test.bat`。新版本必须重新传到手机，旧手机副本不会自动更新。

`PACKAGE-MANIFEST.json` 记录源码文件哈希和对应 GitHub 提交，方便核对包与仓库。生成新包可使用 `tools/package_source.py`，只打包明确列出的源码文件。
