# IEM 多场次选票页真机演练

目标是北京 IEM 淘汰赛，2026-11-06 14:30，一层核心看台单日票，1580 元，1 张。测试入口是安卓猫眼 App，运行器是手机 AutoX。演练到订单核对页结束，未提交订单、未付款。

## 实际发现和修改

- 先前的 AutoX 坐标短按记录显示已调用，但 1580 元票档没有选中；20 毫秒和 60 毫秒的两轮都出现过这个问题。同一标签位置的 ADB 普通点击曾选中。两种方法的时间、页面状态也不同，不能据此断言触摸时长是唯一原因，更不能推断平台启用了防御。
- 改为在刚核对的选票页查找唯一日期/票档/确认文字，重新获取原生节点，并点击它最近的可点击父控件。校验窗口包名、节点唯一性、坐标变化和父控件范围。每步只发出一次 `ACTION_CLICK`，失败后不追加坐标点击。
- 点击后仍检查目标金额、1 张和确认按钮是否就绪。没有库存、金额不符、候选不唯一时不推进。
- IEM 订单标题在字母之间插入 U+200B，不处理会出现“实际已进入订单页，日志却未识别”的错误。文字匹配现去掉 U+200B 和 U+FEFF；原始文字保留给原生节点查询。
- 调试过程中一次 AutoX 无障碍服务处于崩溃状态。恢复服务后重跑。脚本打开菜单与脚本真正开始运行仍须通过本轮启动标识区分。

## 成功一轮的记录

运行记录为 `iem-1580-action-1791890896`。相对时间来自手机端脚本，不包含打开 AutoX 和返回猫眼的准备时间，也不是正式开售时间。

| 动作或阶段 | 耗时 |
|---|---:|
| 日期控件查询与点击调用 | 12 ms |
| 1580 元票档查询与点击调用 | 21 ms |
| 确认控件查询与点击调用 | 14 ms |
| 入口点击至识别选票页 | 920 ms |
| 识别选票页至确认点击完成 | 1457 ms |
| 确认点击完成至识别订单页 | 1413 ms |
| 入口点击开始至识别订单页 | 3790 ms |

结果状态是 `order_review_reached`。这轮证实脚本能完成“11 月 6 日 → 1580 元 → 确认”三个动作；12/21/14 ms 是调用耗时，不是页面跳转总耗时。整个过程还包括页面更新、读取和核对，不能承诺几个毫秒完成、一定优于人工或一定买到票。

当前订单页观演人的原生勾选标志问题仍独立存在，本次没有对一般订单提交能力作验证，也没有把私有观演人绑定补丁加入主模板。

## 验证

AutoX 相关测试 128 项通过。新增测试覆盖日期、票档、确认原生动作、不可点击文字的父控件、不可见字符标题，以及动作被拒绝或出现多个候选时不追加触摸。

现场原始 XML、截图和试验脚本保存在本机 `data/iem-beijing`，包含私人信息，属于运行数据，不应加入公开源码或分享包。

## 追加订单提交演练

用户随后明确要求重启脚本，增加订单页右下角“立即支付”。第二轮从演出详情页重新运行，自动完成日期、1580 元票档、票档确认和一次订单提交，最终识别到猫眼的 1580.00 元支付订单弹窗。脚本状态为 `pending_payment_sheet`，已停止，没有点击弹窗里的“确认支付”，未实际付款。

这次订单提交也在本轮专用脚本中使用原生控件点击，调用耗时 11 ms。观演人沿用用户此前确认的唯一已勾选观演人，专用脚本只接受既有姓名摘要和同一证件摘要；这不是对所有观演人或不同账号的通用勾选验证，私有绑定不在主模板中。

| 阶段 | 耗时 |
|---|---:|
| 购票入口点击开始 → 识别选票页 | 1076 ms |
| 识别选票页 → 日期、票档、确认点击完成 | 1503 ms |
| 票档确认点击完成 → 识别订单页 | 1328 ms |
| 识别订单页 → 开始点击“立即支付” | 173 ms |
| “立即支付”控件点击调用 | 11 ms |
| 提交调用完成 → 识别支付订单弹窗 | 1677 ms |
| 购票入口点击开始 → 识别支付订单弹窗 | **5768 ms** |

这些数值包含页面更新、读取和校验；时间终点是脚本确认弹窗状态，不是服务端内部创建订单的时间。打开 AutoX、切回猫眼和启动准备不计入 5768 ms。运行记录 `iem-1580-60ms-1791891350` 的名称沿用早期短按实验命名，实际四个后续动作在本轮均采用 `accessibility_action`，没有使用 60 ms 短按。
