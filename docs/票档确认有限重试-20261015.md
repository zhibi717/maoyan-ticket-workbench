# 票档确认有限重试（2026-10-15）

此文记录上一版实验。后续复核确认3次、200ms没有真机依据，当前模板已默认关闭该重试；旧实验代码单独保留。当前行为见[确认反馈处理](确认反馈处理与实战验收-20261015.md)。

周深长沙929元实测记录了票档页的一次原生ACTION_CLICK，随后8秒没有识别到订单页。该记录只能证明发出了原生动作，不能证明猫眼业务接受了确认，也不能证明平台识别脚本。此次修改针对“首击无响应后只等待”的缺口。

## 行为

- 日期和票档继续沿用原选择逻辑；`keep_current`仍不点击日期。
- 票档页“确认”改为在新核对按钮范围内屏幕短按。返回失败即停止，不进行第二种接口补点。
- 首次确认后，只有新读取仍确认同一选票页、目标档、目标金额或选中标记、1张和唯一启用确认按钮时才能重试。每次使用新读取的位置，不沿用历史坐标。
- 总次数最多3次，触摸起点至少间隔200ms；正常首击进入订单时没有额外等待。
- 观察到加载、排队、页面变化或覆盖弹层即禁用本组后续重试。不能因为旧选票树再次出现而恢复点击。
- 订单提交仍仅一次。商户支付停止版仍在“支付订单”弹窗停止；普通导出的微信模式保持原边界。选档演练不点击“确认”。

## 记录与对比

`skuConfirmRetry`记录`touchCount`、`maxTouches`、`minIntervalMs`及`stoppedReason`。`touchTimings`逐次记录按钮阶段、发起时间、调用耗时和`screen_touch`或`accessibility_action`方法。调用成功不等同页面跳转成功。

旧模板保存在`autox/versions/maoyan_live_before_confirm_retry_20261015.js`。原周深实测脚本及结果保留，不用新版覆盖旧证据。新脚本需要重新生成、传送后才会在手机生效。

## 验证范围

完整离线回归226项通过，模板和模拟器的Node语法检查通过。用例覆盖首击无响应后恢复、总次数与间隔限制、加载后旧页面重现、日期/金额/数量/按钮位置或启用状态变化、验证弹层、进入订单后停止票档重试，以及订单单次提交和支付停止边界。

本改动未进行真机运行，不能据此给出实际提速数字或成功率。仍需在可售页面做选档确认演练。
