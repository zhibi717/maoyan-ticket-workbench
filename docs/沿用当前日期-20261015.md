# 沿用猫眼当前日期

工作台“猫眼日期处理”新增“沿用猫眼当前日期（不点击日期，直接选票档）”。启用并保存后，重新生成或传送手机脚本才会生效。

适用前提：进入选票页时，猫眼当前显示的场次就是希望购买的日期。脚本仍按工作台指定票价选择票档、确认 1 张并点击票档页确认；是否继续提交及付款停止位置取决于原运行模式。

- 不点击任何日期，也不等待由脚本切换日期触发的刷新。
- 若目标日期存在但 Android 没有暴露选中标记，会按使用者的设置沿用当前日期；不会把“没有标记”当成需要补点日期。
- 如果页面明确显示其他日期已选中，或目标日期不存在，停止；不自动改日期。
- 选档后仍检查票价、1 张数量和确认按钮。订单页必须包含原目标日期、票价和数量才能提交；选票页无法识别默认日期时，不会省略订单核对。
- 开启回流替补后，仍优先原票档；找不到可售目标档时，可以在当前日期选择授权的替补档。此修改没有增加点选失败后的重试；现有的票档点选无响应仍会停止。
- 原“按工作台目标日期选择”模式保留，旧配置默认保持该模式。该模式仍有日期切换异步刷新需要进一步验证的问题，本次修改没有宣称修复该分支。

本机周杰伦三亚配置已选择沿用模式：12 月 18 日、1380 元优先、1 张，允许其他价格可售档。私人生成脚本到猫眼支付弹窗停止，不点击确认支付。

修改前模板：`autox/versions/maoyan_live_before_keep_current_date_20261015.js`。本机私人配置和生成文件另有 `data/backups/keep-current-date-*` 备份。

验证覆盖多个日期但无选中标记、已标记目标日期、其他日期已选中、选档后日期改变、目标日期缺失、授权替补、选档演练，以及订单日期不符时不得提交。模拟特意让“重复点日期”在选档后清掉选择，验证沿用模式避免该刷新。离线验证不能证明真机耗时或有票时的成功率。
