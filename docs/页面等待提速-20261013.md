# 猫眼页面等待读取优化

用户希望继续减少从购票入口点击到支付弹窗的时间，提出约2.7秒的目标。上一轮张智霖1080元完整真机实测为4387ms。两者不能直接视作同条件的速度基准；新版尚未取得完整真机流程成绩。

## 已实现的变化

`autox/maoyan_live_template.js`新增统一的页面转换读取函数。入口、日期切换和票档确认后的页面等待采用以下规则：

- 第一次读取仍保留原来的完整读取。如果新页面已经就绪，不额外增加一次先读文字的查询。
- 尚未识别到目标页时，后续等待只复制实时文字和描述；入口等待额外保留真正购票按钮的位置与启用状态，用于原有的有限同页重试。
- 文字匹配到选票页后，重新完整读取，并再次核对页面；文字快照本身不能用来选档或点击确认。
- 文字匹配到订单页后，观演人处理和提交前仍各自读取并校验当前订单。演出、日期、金额、数量、原观演人和验证/支付阻塞检查没有取消。
- 没有改动订单提交次数、支付停止位置、触摸时长或预设票档；没有增加盲点和连续提交。

读取的是运行时安卓控件树，没有提前打开本场选票页来缓存点击位置。

## 分阶段计时

新增`readTimings`诊断，记录读取开始相对时间、耗时、模式、节点数量和阶段。只保留最近120次读取，使长时间开售等待不会占满后续阶段记录；不记录页面文字、姓名、手机号或证件。现有累计读取统计继续保留。

下一次真机可按同一统计窗口分开比较：入口点击至选票页、选档与确认、确认至订单页、提交核对、提交至核实支付弹窗。不把模拟时钟、单次点击调用或静态页面读取耗时当成完整抢票耗时。

## 验证与限制

离线同一延迟订单场景，旧版与新版均执行64次加载轮询，动作顺序和最终状态相同。加载阶段位置查询从126次减少到2次。这个对照验证减少了不必要的属性读取，不能换算为真实节省多少毫秒，也不意味着总耗时按这个比例下降。

回归检查覆盖加载结束后的新快照、日期变化、验证突然出现、原预选状态变化、错误金额/数量/观演人、支付弹窗优先和不重复提交。新增检查验证加载轮询不反复取坐标，以及阶段计时有界且不含私人字段。

本轮完整流程测试135项通过。网络中断前未保存完成结果的那次不作为通过证据，恢复后重新运行并保存输出。

用户已表示真机稍后再测；本轮未再次购票、创建或取消订单。手机尚未同步这轮候选修改。电脑工作台下一次重新导出脚本时会使用新模板，先前成功实测脚本和原始记录仍保留。2.7秒仍是待验证目标，服务器响应和页面更新耗时不会因为少读坐标而消失。

本机对照数据和测试输出位于`data/transition-reader-20261013`；旧模板备份位于`data/backups/transition-reader-20261013`。这些本机文件不属于公开分享源码。
