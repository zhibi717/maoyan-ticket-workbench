# 任意目标票档与预选恢复

本次基于已合并的 GitHub PR #1 继续修改。修复正式手机预选分支只等确认按钮、预选丢失时不点击票档的问题；1380 元只是某场配置，程序没有固定档位。

## 工作台操作

1. 选择演出，填写你希望买的场次、票档原文（含金额和看台/内场等类别）及唯一观演人，保存。
2. “猫眼票档来源”默认采用工作台填写。任意明确金额均可，例如看台 580 元或内场 2380 元；不会自动改成别的金额或场次。
3. 若希望直接采用手机里的预选，选择“先记录手机明确预选的票档”，保存；点击“记录手机预选”，在手机运行后 20 秒内切到猫眼预约选档页。必须能读出唯一选中的场次、票档及 1 张数量。记录成功后返回演出主详情页。
4. 记录有效期为 24 小时，且绑定本次演出资料与开售时间；修改资料或在手机改选后重新记录。读取不到明确选中状态时，使用工作台填写目标，不猜测红色边框或进入订单后出现的价格。
5. 提前传送正式脚本，在开售前 10 分钟内于手机运行，20 秒内回到目标演出页。需要保持手机解锁、猫眼在前台、AutoX 无障碍开启。

## 实际流程

目标在首次购票点击前固定。进入选档页后，已选目标保持不动；日期或票档未选时，分别点击唯一可用的目标。观察到正确选中状态或匹配的合计金额、1 张、唯一可用确认按钮后，点击确认。已存在选择但无法确认选中金额时停止，避免把已有正确预选点掉。

订单页核对演出、日期、目标金额、1 张及指定实名观演人。需要时补勾唯一匹配观演人一次；明确提交按钮只点一次。订单金额变化时停止；不会自动接受另一档。收银台只尝试明确的微信跳转，进入微信停止，验证码和最终付款在手机完成。

## 验收与限制

离线测试覆盖多种金额、预选保留和丢失、跨脚本记录复用、过期记录、修改资料失效、不可售票档、金额变化、选档未生效及订单不重复提交。此处的测试是合成页面，不代表猫眼真实库存或页面已完成真机验收。

1ms 是首击触摸参数，20ms 是部分等待观察周期，均不是从开售到支付的总时延。网络、页面加载、无障碍树刷新和验证码决定实际耗时；不能保证毫秒级抢到票。每个目标仍限唯一观演人、1 张，不支持同时挑多个备选票档。

安装后须通过工作台重新传送手机文件；手机历史文件不会自动升级。旧版已在电脑单独备份，可恢复。

## 拥堵弹窗持续刷新

正式手机脚本已包含此流程：同时识别“前方拥堵”和“请刷新重试”，核对底页仍是本次目标订单或票档，只操作拥堵弹窗内的刷新按钮。每次重新读取页面，触摸起点至少间隔 400 毫秒；持续到原开售后 20 分钟或 3000 次上限，弹窗消失后恢复原流程。出现验证或支付页时结束刷新，订单不会重复提交，最终付款仍由使用者完成。

补充了弹窗归属校验：文案与刷新按钮须属于同一个有明确边界的父容器，排除整个窗口根及包含底页订单信息的容器。若仅底页存在同名按钮，或无法读取弹窗归属，就停止，不猜位置。只读检查和选档演练不会刷新。

这套逻辑需要能从辅助功能读取弹窗结构及底页目标；完全遮挡底页、详情页上的拥堵或未知弹窗布局不自动处理。离线模拟不能证明真实 Android 拥堵页面已适配，仍须真机只读检查。新增测试区分弹窗与底页同名按钮，不操作手机或真实订单。
