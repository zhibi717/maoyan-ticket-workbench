# 猫眼选票页兼容修复与真机记录（2026-10-13）

欧阳娜娜成都站 580 元正式流程在选票页提前退出：无障碍控件没有提供 selected 标记，脚本却把“没读到请选择票档”当作已有选择，阻止了目标票档点击。本次修复处理未预选、预选已生效、预选价格不同三个状态。

## 修改后的行为

- 猫眼没有选好目标档位时，脚本对唯一可售目标票档点击一次，再检查实际数量、合计金额和确认按钮。
- 目标已选好但 selected 标记缺失时，使用底部合计、1 张数量和唯一可用确认按钮交叉验证；确认前重新读取核对。
- 底部“总计:￥”和金额分属不同控件时，按同一行相邻位置组合。底部金额不再参与票档候选匹配。
- “每单限购 6 张”属于限购说明；仅将独立数量控件“1张”等作为购买数量。
- 唯一场次已显示票档时保留当前场次，避免再次点击日期重置预选票档。多场次继续选择配置的日期；确认前再次核对场次条件。
- 入口仍使用 1 ms 短按；票档、确认等后续控件改用 20 ms 短按。实际调用和页面更新分别记录，不将调用耗时当作跳页耗时。
- 新增独立确认选档演练：选档后确认到订单核对页即结束，不勾选观演人、不提交、不支付、不占用正式尝试标记。

## 真机实验

用户授权从详情页进入选票页，改选 780 元，再点击票档页右下角确认。使用同一台已授权 USB 安卓手机、猫眼 App、AutoX 服务。正式工作台配置继续保留原目标，实验使用单独生成文件和演练开关。

第一次实验已发出入口、日期和票档短按，但票档未选中，未继续点击确认。随后取消唯一日期下的多余点击，并将非入口短按时长从 1 ms 改为 20 ms；这两项改变在同一轮应用，不能凭结果单独断定其中哪项导致第一次点击不生效。

第二次实验完成：页面显示看台 780 元 × 1 张，进入“确认购票”核对页；脚本结果状态为 `order_review_reached`，点击记录只有入口、目标票档和票档确认。

| 实测区间 | 耗时 |
| --- | ---: |
| 入口开始点击 → 识别到选票页 | 907 ms |
| 识别选票页 → 开始点击 780 元 | 30 ms |
| 开始点击 780 元 → 观察到数量、总计及确认就绪 | 356 ms |
| 完成选档核对 → 开始点击确认 | 20 ms |
| 确认开始点击 → 识别到订单核对页 | 1,177 ms |
| 入口开始点击 → 订单核对页 | 2,490 ms |

票档点击调用为 23 ms，确认点击调用为 23 ms。上述页面区间包含 App 页面更新、网络响应和脚本观察时间；仅为这一次真实运行，不是重复实验分布，也不保证开售高峰耗时或抢票成功。

原始诊断及两轮实验结果保存在本机 `data/nana-failure-20261013/`，含截图、控件树和生成脚本，属于本地运行资料，不进入分享包。

## 验证

相关 AutoX 测试 125 项通过。其中使用实际安卓选票页的控件结构制作通用占位测试数据，覆盖无 selected 标记、拆分总价、限购说明、无占位提示、错误合计、2 张、1580/580 精确匹配、确认前金额变化。选档演练保留不点击确认的原行为，新增确认演练单独测试。

本次脚本能在开启 AutoX 的同一手机选择票档并进入核对页；没有取得平台检测或防御脚本的直接证据。仍不能根据这次普通售票实验推断开售库存或平台风控行为。
