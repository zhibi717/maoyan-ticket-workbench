# 入口等待优化与验证

本次针对那英1180元上一轮实测的入口至选票页1174ms继续减少脚本开销。该成绩是点击至程序完成页面识别的时间，不是页面首帧显示时间。上一轮读取405ms、读取之间等待749ms；等待时猫眼也在加载，不能把749ms全部当作可直接省掉的时间。

## 代码变更

- 入口点击后，检查周期由80ms改为20ms。周期扣除当次读取时间；若读取已超过20ms，仅让出2ms，避免持续占用无障碍服务。读取本身较慢时，实际检查周期仍可能超过20ms。
- 入口等待的第一次检查也使用轻量模式，只取页面文字、描述和购票入口所需的位置与状态；加载页不再先完整复制所有控件的坐标。
- 同一次读取若已包含“选择票档”及唯一目标日期，释放当前安卓节点前补齐选票所需的位置和状态，省掉原来的第二次整树获取与文字遍历。补齐属性也需要时间，不等于零耗时。
- 日期、票档真正点击前仍重新读取当前页面并校验；没有缓存其他场次的图片或坐标，没有移除金额、数量、观演人和订单提交前的核对。
- 临时保留的安卓节点在成功、读取异常和补齐属性异常时均释放；节点数量和读取总时长仍有上限。

其余步骤、有限同页入口重试、订单提交次数和支付停止位置保持原有行为。本次没有调整支付弹窗、创建或取消订单。

## 保留的上一版

`autox/versions/maoyan_live_before_entry_poll_20261014.js`保存本轮改动前的模板。模板没有用户目标资料，默认关闭运行开关，可供同条件对照。之前保存的预选判断版和成功实测脚本也保留。

## 验证

执行`node --check autox/maoyan_live_template.js`和`node --check tests/autox_live_mock.js`，语法检查通过。

执行`.venv/Scripts/python.exe -m unittest tests.test_autox_live_export`，140项测试通过，用时48.968s。新增测试覆盖：

- 同一模拟页面在点击后96ms就绪、每次加载读取消耗5ms时，旧版在165ms完成入口页识别，新版在105ms完成，动作和终点相同。这60ms是模拟调度验证，不能作为真机提速成绩。
- 页面已就绪时没有增加整树读取次数；延迟就绪时，选票页的整树读取减少一次。
- 每次读取耗时75ms时，仅额外让出2ms，没有再完整等待20ms。
- 读取或补齐属性失败时没有遗留、重复释放安卓节点，也不泄露页面内容。
- 新快照的日期变化、验证码、错误票档/数量/观演人、重复提交及支付停止边界继续通过原有回归。

## 当前部署与测速状态

代码改完时USB未连接。随后用户连接手机并授权杨千嬅11月21日1098元测试，已生成、同步和运行新版试验脚本。真机从入口点击至选票页识别925ms，从入口至支付弹窗5022ms；此前同场为1218ms和5023ms，入口减少293ms但全程基本不变。不是受控A/B，不能把变化全算作本轮修改的收益。完整记录见`杨千嬅1098入口新版真机测速-20261014.md`。

工作台下次重新导出的脚本会采用新模板；其他已经导出的电脑或手机脚本不会自行更新。

20ms是检查周期设置，不是保证20ms完成跳页，也不代表整段抢票可在几毫秒内完成。下一步评价改动仍需同条件记录，不能用单次点击调用或静态页面读取来代替完整流程。
