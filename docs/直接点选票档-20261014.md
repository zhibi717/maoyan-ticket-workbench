# 进入选票页后直接点选目标票档

用户要求减少判断猫眼是否恢复预选票档的步骤。普通选票流程现已改为：按配置场次找到唯一可售的目标票档，直接点击一次，再核对选票结果并点击确认。不先用选中标记、合计、张数和确认按钮来判断是否应跳过这次票档点击。

目标价格来自工作台资料，未固定为1080或1380元。相关用例包含480、580、780、980、1080、1380、2380元。日期选择逻辑继续使用配置场次；缺货、重复价格卡片和不明确的页面不会作为可点击目标。

点击后仍取得当前页面，核对1张、目标合计和唯一可用的确认按钮，然后确认一次。订单核对、观演人检查、提交一次和支付弹窗停止规则保持原有含义。选档演练仍不点击确认。

诊断`skuDecision`现在记录`selectionMode: explicit_click`和`preselectionChecked: false`。之前用于“保留猫眼预选票档”的分支已删除，点击后的选档结果检查仍保留。

## 速度与行为差异

旧版预选判断主要使用已读取的当前快照，没有专门等待猫眼自动勾选的固定几百毫秒延迟。删除这些判断不能直接从上一轮4.387秒中减去某个已知数值。

新版流程更直接，并始终由脚本设置目标票档。如果猫眼本来已正确预选，旧版可能省一次点击，新版会多点一次并读取点击后的更新，因此未必更快。若同一票档重复点击会清空选中状态，模拟检查确认程序会停下，不重复选档或继续确认；本机猫眼此行为仍需真机核验。

本轮没有再次操作手机。用户此前表示真机稍后再测，新版尚未同步手机，尚无新的完整真机耗时或2.7秒成绩。保留旧版备份供对照。

验证覆盖普通未预选、已预选但仍直接点一次、缺少Android选中标记但有分拆合计、点击后金额/张数错误、日期变化、重复点击取消选择、重复票档和提交次数。已有用例中“跳过票档点击”的预期已按本次用户要求改为“目标票档只点一次”，缺货和错误订单检查没有取消。

AutoX导出和流程测试136项通过，耗时45.044秒；JavaScript语法检查通过。这些是离线验证，不是新的真机速度成绩。
