# 猫眼四页流程与入口优化（2026-10-12）

详情页购票入口 → 指定场次票档及1张、自动确认 → 确认购票页保留或匹配指定实名观演人、提交一次 → 猫眼支付订单弹窗 → 微信实际付款页停止。

猫眼的支付订单弹窗必须具备独立的底部容器、支付剩余时间、支付方式、唯一可用确认支付按钮。仅核对弹窗内部唯一目标金额，不能用底层订单金额替代；唯一已选微信方式核对后才尝试跳转一次。不会对微信的最终确认、密码或验证发送操作。未知范围、金额变化、多个支付方式同时选中、自动扣款提示或跳转结果不明确时停止，不重复提交或唤起。

星号姓名仅兼容用户已预选的唯一已勾选观演人，且显示掩码须与保存姓名的常见掩码摘要匹配。完整姓名原匹配方式保留；未勾选的掩码姓名、全星号或多候选不自动选择。个人配置、生成脚本和截图仍只在本机，开发源文件不包含姓名片段。

入口热轮询一次fresh读取完成所有身份和验证文本检查，以及入口范围与可用状态判断；免去找到候选后额外遍历整页。初始预检标签树及开售前开始读取的树不得用于动作。已核对的入口、场次、票档、确认、观演人补勾、订单提交及猫眼微信跳转均采用同一短触摸方式；1ms仅是按压参数，不是总响应时延。若一次短触摸失败，停止而不改用普通点击补点。拥堵刷新间隔保持至少400ms。

运行记录分开保存screenRootReadMs、screenTreeCopyMs、entryDecisionReadMs、entryDiscoveryToClickMs、entryClickCallMs、entryClickToNextPageObservedMs及每步touchTimings。发现到点击指标不包含发现前的读取耗时，下一页观察指标包含App转换和脚本识别，不应称为纯网络耗时。

验证：AutoX测试116项、其余工作台测试60项通过，总计176项。合成验证证明调用顺序、金额和状态守卫、跨开售快照及验证保护、失败不重复点击；不能证明真实票可售或真实跳页延迟。本次优化尚未取得新的Android真机速度成绩。

目标票档来自本机保存或明确记录的预约资料，不从参考截图或未知订单价格推断新目标。实际使用须在工作台重新传送手机脚本，历史手机文件不包含本次更新。本机更新前的版本仍可从本机备份恢复；源码发布不包含私人备份或配置。
