# 确认反馈处理与实战验收

本次修改针对周深929元实战中“确认调用后短暂增加节点，却没有记录提示内容”的证据缺口。没有在手机运行或创建订单，没有据此宣布查明平台内部原因。

## 现有已修正的路径继续保留

- 开售前接受“已预约”或唯一购票入口，开售后使用新的可用状态；正式首击仍按配置时刻等待，避免旧预约状态导致触摸前退出。
- `keep_current`模式不点击日期，避免不必要的场次刷新；显式冲突日期和订单日期仍核对。
- 进入选票页明确点击配置票档，再等待票档、1张和确认控件生效，避免旧版在未选档时直接退出。这里没有增加新的日期点击或预读坐标。

## 本次新增

1. **动作结果分开记录。** `touchTimings`保留动作类型、发起时刻和调用耗时，新增`apiReturnedSuccess`、`callThrew`。返回失败或调用异常在对应阶段停止，不能将API返回成功当成订单推进成功。标准`press()`路径没有提供本项目独立记录的手势完成/取消回调，此状态仍未测量，不能从返回值猜测。
2. **复用现有读屏记录反馈。** 确认发出后，从原有树快照提取固定类别和节点数；状态变化时保存，缓冲最多32条，不额外取得窗口根或读取节点属性。`feedbackCaptureMs`另记分类处理耗时。分类包括库存不足、请求异常、加载、拥堵、验证、订单标记和付款标记。
3. **监听短暂Toast。** 只接收猫眼、且本轮确认等待期间的事件，存固定分类和回调接收时刻；未知内容标为`unclassified_toast`，不保存姓名、手机号、提示原文。独立监听线程通过容量64的Java队列传递分类，购票线程读取后决策；退出时移除自己的监听并中断自己的线程。记录监听支持、启动和异常情况，不能将“注册过监听”当成“真机一定捕获了事件”。
4. **按反馈说明结果。** 确认后收到明确库存不足或请求异常，且当前还未显示订单核对标记时及时停止并报告原因，不再等到通用8秒跳转超时。加载继续观察，验证和已识别拥堵沿用已有处理；确认进入订单则结束本组观察。出现订单标记时仍须通过原来的目标身份和金额检查才能提交。
5. **撤下未经证实的默认连点。** 默认`ENABLE_SAME_PAGE_CONFIRM_RETRY=false`。3次、200ms旧方案保存为实验对照，离线对照测试显式开启。当前没有将不明结果改造成无条件重复确认；没有缩小参数后宣称更快。原8秒观察预算继续保留，也不是性能极限。

Toast不能在购票主循环中简单注册后就假定及时工作：[AutoX事件文档](https://github.com/aiselp/AutoxDoc/blob/main/docs/rhino/advanced/events.md)说明事件回调会被同线程耗时操作和轮询阻塞。本实现使用[AutoX线程文档](https://github.com/aiselp/AutoxDoc/blob/main/docs/rhino/advanced/threads.md)所述的独立线程事件循环，跨线程不共享可变的JavaScript记录数组。其Android实际回调时机与设备兼容性仍待真机验证。

## 仍未完成的部分

本次完整离线回归234项通过，模板及模拟器的Node语法检查通过。新增覆盖提示来自树或Toast、调用失败及异常、未知/其他应用/确认前提示过滤、监听能力缺失与失败、事件突发时缓冲上限、监听和线程清理。成功路径与上一版对照的窗口根读取次数、几何及属性读取次数一致；这只能证明模拟中没有增加Android读屏调用，不能证明真机CPU开销为零或真实开售更快。

当前修改提供明确失败分流与定位资料，不是库存或平台风控绕过方案。未知提示不保存原文，仍可能需要视频或现场截图补充。也没有精确屏幕首帧、服务器时钟偏差或猫眼网络请求内部耗时数据。

下一轮先在可售页只做“票档确认→订单核对页”对照，不必点击立即支付。分别验证原生点击与屏幕短按、Toast是否在购票线程轮询期间及时被捕获、错误消失后的页面状态，以及第一次进入页面的表现。新旧都保留首次失败；不只取成功重跑，不将日常成功视为开售稳定性证明。确定无响应原因后，再决定是否需要重试及间隔。

本机已生成关闭正式执行开关的独立准备文件，旧周深实测源文件和结果未覆盖；尚未同步手机。公开通用导出的停止位置没有改变，商户支付停止版仍停在猫眼支付弹窗。
