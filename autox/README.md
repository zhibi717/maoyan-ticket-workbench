# 猫眼 AutoX 手机端

正式导出使用build_wechat_script，启用USER_PRESELECTED、SUBMIT_TO_PAYMENT及OPEN_WECHAT_PAYMENT。模板本身保持锁定，运行时由本机配置生成脚本，不上传个人生成文件。

1. 工作台保存并选中猫眼目标，配置正确演出城市、日期、开售时间及唯一观演人。
2. 手机登录猫眼、提前选好场次票档与1张票，开启AutoX无障碍。
3. 连接已授权USB，点击“打开 AutoX 到微信付款页脚本（不付款）”，文件传到手机下载目录autox-maoyan-live.js。可提前传送；正式运行在开售前10分钟至开售后20分钟窗口内。
4. 手机选运行脚本，20秒内切回目标页面，保持解锁和前台。脚本等待开售按钮可用后推进。
5. 核对目标、1张及唯一指定观演人后单次提交。确认购票页立即支付可用于创建订单及默认微信唤起；收银台需要明确微信跳转按钮或明确选中微信。进入微信即停止，由使用者付款。

手机预选模式在首击前不核对原生selected字段或电脑配置票价，不切换用户选择。订单日期仍须匹配配置；订单实际价格唯一明确时接受，并用于收银台与微信金额核对。金额不明确、验证、目标变化、未知布局或自动扣款选项交给使用者。提交或微信唤起不明确不会重复操作，不对微信发送点击、输入或手势。

首击使用press(x,y,1)，保留新页面、唯一启用候选与范围核对。1ms是触摸参数，不是全流程时延。首击后丢弃快照并读取下一页，减少无必要字段读取和重复匹配；开售最后3秒及入口等待采用20ms观察周期，扣除读取耗时。

同时识别“前方拥堵”和“请刷新重试”、匹配目标及唯一刷新控件时自动刷新。触摸起点至少间隔400ms，仅原开售后20分钟窗口内，最多3000次；页面变化重新检查，不重复提交订单或点击底层支付。

工作台另提供选票档演练（不确认不下单）和拥堵只读检查（不点击），只读与演练不占用正式尝试锁。正式脚本在AutoX私有目录保存单次尝试标记，出现不确定结果须先核对猫眼订单。

工具tools/autox_first_click_benchmark.js仅在AutoX本地界面测按钮启用至触摸回调，不操作猫眼或微信。需约20秒前台不操作手机，成功显示Complete:24 local trials，结果在手机下载目录qiangpiao-first-click-benchmark.json。详见docs/优化验收-20261012.md。

尚未完成真实开售、创建订单及微信SDK跳转的整条真机验收；局部测速和离线测试不能保证抢票概率或最快。更新工作台后须重新传送正式脚本，避免运行手机历史旧文件。
