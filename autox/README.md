# 猫眼 AutoX 手机端

## 只读检测

此脚本用于确认 AutoX v7 的无障碍读取是否能在你的手机上识别猫眼当前页面。它不点击、不滑动、不提交订单，也不读取截图。检测结果只输出“找到/未找到”，不记录页面原文或观演人信息。它不能证明票档已选中或保证抢票成功。

1. 在电脑工作台保存并选中**猫眼、1 位观演人**的演出。
2. 在项目目录运行 `.venv\Scripts\python.exe -m ticketdesk.autox_export`，生成 `data/autox-maoyan-probe.js`。生成文件仅含演出关键词、城市、目标日期和金额；不含观演人姓名或设备序列号。
3. 用 USB 文件传输把这个 `.js` 文件放到手机“下载”目录，或在 USB 已授权时运行 `tools\platform-tools\adb.exe push data\autox-maoyan-probe.js /sdcard/Download/autox-maoyan-probe.js`。
4. 在 AutoX 中打开该文件，确认无障碍服务已开启后运行。看到提示后，20 秒内手动切到猫眼目标演出页。脚本只检查当时可见的页面，运行后回 AutoX 看日志。

日志会分别报告 12 次演出关键词与城市查询、逐词购票入口查询、正则合并入口查询的最短、中位、最长耗时。这只是手机本地控件选择器耗时，不是从开售到订单或支付页的总耗时。脚本用辅助功能的活动窗口确认猫眼；这台手机的 `currentPackage()` 曾滞留在系统桌面的包名，不能作为前台判断。详情页可能不会显示目标日期或金额，因而这两项“未找到”不代表资料错误。预约设置页的红色爱心是否选中仍须使用现有工作台的 USB 探测或目视确认。

2026-10-08 在已预约的周杰伦广州详情页实测，12 次查询的中位耗时分别是演出与城市 6 毫秒、逐词入口 23.5 毫秒、正则合并入口 4.5 毫秒；最长分别为 1089、7202、1152 毫秒。此时尚未开售，入口查询均未命中。这组结果只说明合并查询在当前页面更快，且存在秒级长尾；它不能证明开售后的选票、提交、验证或支付流程速度。一次逐个读取约 448 个页面节点的中位耗时为 623.5 毫秒。这是旧版检测结果，不能用于新版完整流程的速度宣传。

2026-10-09 在三亚详情页运行正式模板的只读分支，重复使用普通模式选择器的整组检查耗时 12697 毫秒。新版改为每个判定阶段读取一次 Android 原生辅助功能树，在内存中查询文字、价格、日期、按钮与勾选状态；点击前重新读取，点击后丢弃旧数据，等待页面更新时也重新读取，不跨点击复用旧控件。最终真机单次样本为 649 毫秒，其中一次页面树读取 592 毫秒；没有测量稳定中位数。读取上限为 1000 个控件和 2 秒，异常时停止，不输出页面原文。接口依据 [Android AccessibilityNodeInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo)。测速是页面判定耗时，不含启动后的 20 秒切换准备、平台网络、库存和验证时间，也没有证明实际可点中票档。

`autox-maoyan-flow-probe.js` 使用正式模板相同的识别逻辑，但只报告当前详情、选票或订单页，不点击、不创建尝试标记。为避免手机日志缓冲区清除导致结果丢失，只读分支会在手机下载目录保存 `qiangpiao-readonly-result.json`，只含完成时间、阶段、耗时和固定说明，不含姓名、页面原文或摘要。正式脚本不会写这份检测记录。

AutoX v7 默认用 Rhino 引擎运行 `.js` 文件；本脚本采用该引擎的 `auto.waitFor()`、辅助功能活动窗口和只读控件选择器。参考 [AutoX v7 引擎说明](https://autox-doc.vercel.app/docs/nodejs/intro) 与 [控件读取文档](https://autox-doc.vercel.app/docs/rhino/base/widgetsBasedAutomation)。

## 开售后自动选档

手机如仍留有旧版 `autox-maoyan-live.js`，不要直接从 AutoX 历史列表运行；须从新版工作台重新打开脚本，使 USB 传送覆盖旧文件。

`maoyan_live_template.js` 原文件保持锁定。工作台“打开 AutoX 自动选档脚本”会针对所选的猫眼演出生成已启用的本机文件，通过 USB 放入手机“下载”目录，并让 AutoX 显示“运行脚本”菜单。开售前 10 分钟起可启动；点击运行后，20 秒内切回猫眼目标演出详情页，保持解锁。脚本在手机端等待开售并操作，不经过电脑逐步发指令。配置仍要求 1 位观演人以确定 1 张票，但生成的 AutoX 脚本不包含其姓名。

脚本在目标开售窗口内读取猫眼前台页面，只点击唯一识别的购票入口、目标日期和目标票档。若日期已经被页面明确标为选中，则沿用该日期。点中票档并检测到“请选择票档”提示消失后，正式脚本还会核对 1 张与右下角唯一可用的“确认”按钮，点它一次并观察是否进入订单页。随后按下文规则检查指定观演人的勾选状态，再由你操作；选档演练不点“确认”。首次购票点击前在 AutoX 私有目录创建尝试标记，脚本中断后也会阻止自动重复尝试。目标票档不可售、页面未知、出现多个候选、验证或支付出现时即停止。已在真实详情页通过普通模式只读预检；AutoX 的 `fast` 缓存模式在这台手机上误判前台，故不启用。修正后的实际选档与“确认”跳转仍需在可售票档的真实页面验证。

2026-10-08 周杰伦广州站实售中，手机端已快速进入“选择票档”页，但没有点中目标 1380 元，订单未提交。旧版误把“确认/数量/张”等选档后才可能出现的字样作为识别选票页的前提；后续检查又发现票档页本身不显示演出标题和城市，不能在这一页用它们识别。用户约 5 秒后发现未选中；这不是脚本耗时的实测值。随后页面显示 12 月 5 日各档“缺货登记”，不能据此断定开售瞬间的库存。现已按真实截图改为用猫眼前台、"选择票档"和唯一目标日期识别该页，并增加已选日期标记判断、点档后按钮状态检查及阶段时间记录；**这些修改仅通过离线模拟，尚未在可售票档的真实猫眼页面验证，也未证明可在 2 秒内进入下一页**。

工作台另有“选票档演练（不下单）”：在其他有可售票档的猫眼演出详情页，使用对应演出资料即可启动，不受开售窗口限制。它只点击购票入口、目标日期和目标票档，确认右下角“请选择票档”已变化后停止；若直接进入订单页也会立刻停止。演练不会点击“确认”、提交订单，也不会占用正式脚本的一次尝试标记。演练仍需真机验证；不能用尚未开售的三亚页提前证明可选中 1380 元。

2026-10-09 根据用户提供的猫眼流程截图补齐订单页识别：带“确认购票”“实名观演人”的核对页即使底部写“立即支付”，仍按订单页处理。正式脚本会核对演出、城市、日期、金额和 1 张，在观演人区域匹配本机指定姓名，并检查唯一的 Android CheckBox。已选时保留；未选时点一次，最多观察 600 毫秒等待勾选状态更新。没有匹配姓名、出现多个框、控件不可用或状态未更新时停止。随后由用户处理提交、验证与支付，脚本不点击“立即支付”。选档演练不操作观演人。

生成文件包含指定姓名的 SHA-256 摘要，用于本地匹配，不包含姓名原文或证件；摘要并非加密，生成文件仍只应保存在自己的设备。日志不输出姓名、摘要或页面原文。截图展示的是 iPhone，不能证明 Android 猫眼会暴露相同控件；标准 CheckBox 和具有可勾选属性的自定义控件均支持，不提供勾选状态的自绘图片框仍需另行适配。不能从截图校准坐标后直接用于另一台手机。新增逻辑已做离线测试，**观演人控件与完整流程仍需 Android 真机验证**。

已选票档只有在辅助功能明确标记目标金额为选中时才沿用，并继续点击票档“确认”。价格控件禁用、紧凑票档卡中单独显示“缺货登记”时不点击。原型使用的单次控件点击与本地存储 API 见 [控件操作](https://autox-doc.vercel.app/docs/rhino/base/widgetsBasedAutomation) 和 [本地存储](https://autox-doc.vercel.app/docs/rhino/base/storages)。
